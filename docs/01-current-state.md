# 현재 상태 (Baseline Audit)

작성일: 2026-08-28 (Sprint 0~5 완료 + Gemini 전환 — **AI 실사용 검증 완료**, 배포는 미완료)

PRD가 요구하는 최종 형태와, 지금 리포지토리에 실제로 존재하는 것 사이의 간극을 정리한다. 스프린트 계획(`03-sprint-plan.md`)은 이 간극을 메우는 순서다.

## 구현되어 있는 것

- **알고리즘 검색(기능 A)** — 실제 AI 연동으로 동작하며, **실제 성공 응답까지 확인됨**.
  - `lib/algorithm-catalog.ts`: **273개** 항목의 유효 알고리즘 목록(PRD 3.1). 2026-08-28에 두 차례 확장했다 — ① 기초(학부 수업/일반 코딩테스트) 82개에 QOJ(Universal Online Judge) 수준(ICPC World Finals/IOI/CCPC/Petrozavodsk 캠프급 문제 에디토리얼에서 실제로 쓰이는) 고급 알고리즘 143개를 추가(카테고리도 기하/다항식/게임이론 3개 신설), ② 사용자가 제시한 USACO Guide류 종합 커리큘럼 목록을 병합해 48개를 추가(카테고리 `기초` 신설, 담금질 기법·좌표 압축 등 1차에서 "애매"로 보류했던 항목도 재검토 후 포함). 두 확장 모두 SQL/동시성 프로그래밍/인터랙티브/Design 같은 "문제 유형 태그"나 미적분학/물리학 같은 순수 학문 분야는 알고리즘이 아니라서 계속 제외했다.
  - `app/api/algorithm/route.ts` + `app/api/algorithm/code/route.ts`: 설명·난이도·근거·사용처·관련 알고리즘 생성. **2026-08-28부터 최초 요청은 기본 언어(C++) 코드 하나만 생성**하고, 나머지 3개 언어는 그 탭을 열 때 `/api/algorithm/code`로 그때그때 요청한다 — 카탈로그가 273개로 커지며 4개 언어를 한 번에 요청하면 정상적으로도 10초~2분씩 걸리는 문제가 있어 바꿨다(사용자 실사용 중 타임아웃 오탐 발생으로 발견). 실측 결과 최초 요청이 14초대로 줄었다.
  - `components/language-tabs.tsx`: 언어 탭, 세션 내 선택 유지(3.2). 탭을 처음 열면 자동으로 그 언어를 요청(로딩 스피너 표시)하고, 요청이 실패한 경우에만 "불러오지 못했습니다 + 다시 시도" 버튼을 보여준다(5.19) — 이 둘을 구분해 "아직 안 불러옴"을 "실패"처럼 보이지 않게 했다.
  - 관련 알고리즘: 서버·클라이언트 이중 자기참조/무효 id 필터링(5.9, 5.10).
- **문제 검색(기능 B)** — 실제 AI 연동으로 동작하며, **실제 성공 응답까지 확인됨**.
  - `app/api/problem/route.ts`: 난이도·근거·매칭 여부(`matched`)·풀이별 목록 생성, 무효 `algorithmId` 필터링.
  - `components/problem-result.tsx`: 풀이 여러 개면 탭 + 시간복잡도, 매칭 없음은 정상 결과로 안내(5.8).
- **예외 처리(PRD 5장)** — 19개 항목 전부 코드로 구현됨(5.1~5.19).
  - **단일 상태 계산**: `app/page.tsx`의 `getDisplay()`가 `inputError`/`isOffline`/`requestPhase`/`isSlow` 네 원시 상태를 우선순위(입력오류 > 오프라인 > 로딩·지연 > 타임아웃·서버오류 > 성공)로 조합(5.18).
  - 빈 입력 포커스/강조(5.1), 무의미 입력 차단(5.2), 카탈로그 불일치 처리(5.3), 지연(5.4)·타임아웃(5.5), 무제한 재시도(5.6), 필드 단위 부분 파싱 복구(5.7, `lib/ai.ts`의 `generatePartialSafe`), 매칭 없음 정상 처리(5.8), 무효 관련 알고리즘/자기참조 필터링(5.9, 5.10), 로딩 중 탭 전환까지 차단(5.11), 온라인/오프라인 감지(5.12), 글자 수 제한(5.13), XSS 안전(5.14), 클립보드 성공/실패 피드백(5.15, 5.16), 모바일 터치 타겟/키보드 회피(5.17), 상태 우선순위(5.18), 언어별 개별 재시도(5.19).
- **Sprint 5(QA)에서 발견해 고친 것**: `app/page.tsx`에 React 에러 바운더리가 없어, 결과 렌더링 중 예기치 못한 오류가 나면 헤더·탭·입력창까지 전부 죽어 Done Criteria #6("항상 상태 표시줄과 입력 UI는 살아있어야 한다")을 위반할 수 있었다. `components/result-error-boundary.tsx`(`ResultErrorBoundary`)를 새로 만들어 결과 렌더링 구간만 감싸도록 수정 — 이제 그 구간 오류는 결과 영역만 재시도 화면으로 바뀌고 나머지 UI는 그대로 살아있다.
- **2026-08-28: AI 프로바이더를 Vercel AI Gateway → Google Gemini 직접 호출로 전환** (`02-architecture.md` §1 참고). 처음 설계했던 `AI_GATEWAY_API_KEY`가 계속 인증에 실패해, 사용자가 보유한 **Google Gemini API 키**로 갈아탔다. `@ai-sdk/google` 설치, 환경변수는 `GOOGLE_GENERATIVE_AI_API_KEY`, 모델은 `gemini-3.6-flash`(가장 최신인 `gemini-3.7-flash`는 이 시점 503 과부하 중이라 Google이 안내한 안정적인 후속 모델을 선택). `lib/ai.ts`의 `MODEL` 상수 하나로 세 라우트가 전부 이 프로바이더를 쓴다.
- **처음으로 실제 AI 성공 응답을 확인함**: `/api/algorithm`(이진 탐색 — description/difficulty/difficultyReason/useCases 4개/C·C++·Java·Python 코드 전부 정상), `/api/problem`(회의실 배정 문제 — matched:true, 풀이 2개, 유효한 algorithmId, 시간복잡도 포함), `/api/algorithm/code`(퀵 정렬 Python 단일 언어 재생성) 세 라우트 모두 실제 200과 함께 스키마에 맞는 완결된 데이터를 반환함을 로컬 서버에서 직접 확인했다. Sprint 0~5 내내 "코드는 있지만 AI 응답은 못 봤다"던 가장 큰 미검증 항목이 해소됐다.
- **검증 완료 범위**: `tsc --noEmit`, `pnpm build` 모두 통과. 세 API 라우트의 실패 케이스(400/404/502) 10가지 + 이번의 실제 성공 케이스 3가지 전부 확인. `login/payment/upload/저장하기` 등 범위 밖 UI가 코드에 전혀 없음을 grep으로 확인(Done Criteria #7). XSS 페이로드 서버 라운드트립 확인(5.14).
- **아직 못 한 것**: (1) 이번 세션은 브라우저 자동화 도구 없이 진행되어, 실제 AI 응답이 화면에 정확히 렌더링되는지·지연/타임아웃/오프라인/클립보드/모바일 반응형 등의 브라우저 육안 확인을 못 했다(API 레벨로는 확인됨), (2) `generatePartialSafe`의 `'partial'`(스키마 일부만 깨진 응답 salvage) 경로는 지금까지 관찰한 응답이 전부 완전했어서 아직 실제로 발동해본 적이 없다, (3) Vercel 프로덕션 배포는 사용자 본인의 로그인(OAuth)이 필요해 진행하지 못함 — CLI는 설치해 두었다(`vercel --version` 확인됨).

## 결론

Sprint 0~5로 PRD 4장(핵심 파이프라인)과 5장(예외 처리) 19개 항목 전부의 **코드가 갖춰졌고**, 2026-08-28 Gemini API 키로 전환하면서 **AI가 실제로 스키마에 맞는 완결된 응답을 준다는 것이 처음으로 증명됐다**(세 라우트 전부 실제 200 확인). Sprint 5 QA 과정에서 에러 바운더리 부재라는 실제 버그도 하나 발견해 고쳤다. 남은 병목은 이제 하나뿐이다 — **사용자 본인의 Vercel 로그인**(배포용). 코드/AI 레벨 검증은 사실상 끝났고, 남은 건 브라우저 육안 QA(Sprint 6, 도구가 연결되면 진행)와 배포다.
