# 현재 상태 (Baseline Audit)

작성일: 2026-08-28 (Sprint 0~4 완료 시점 기준)

PRD가 요구하는 최종 형태와, 지금 리포지토리에 실제로 존재하는 것 사이의 간극을 정리한다. 스프린트 계획(`03-sprint-plan.md`)은 이 간극을 메우는 순서다. 스프린트가 끝날 때마다 이 문서 전체를 그 시점 기준으로 다시 쓴다(이력은 git으로 추적).

## 구현되어 있는 것

- **알고리즘 검색(기능 A)** — 실제 AI 연동으로 동작한다.
  - `lib/algorithm-catalog.ts`: 82개 항목의 유효 알고리즘 목록(PRD 3.1).
  - `app/api/algorithm/route.ts` + `app/api/algorithm/code/route.ts`: 설명·난이도·근거·사용처·C/C++/Java/Python 코드·관련 알고리즘 생성, 언어 하나만 개별 재생성(5.19).
  - `components/language-tabs.tsx`: 언어 탭, 세션 내 선택 유지(3.2), 실패한 언어는 탭 안 재시도 버튼.
  - 관련 알고리즘: 서버·클라이언트 이중 자기참조/무효 id 필터링(5.9, 5.10).
- **문제 검색(기능 B)** — 실제 AI 연동으로 동작한다.
  - `app/api/problem/route.ts`: 난이도·근거·매칭 여부(`matched`)·풀이별 목록 생성, 무효 `algorithmId` 필터링.
  - `components/problem-result.tsx`: 풀이 여러 개면 탭 + 시간복잡도, 매칭 없음은 정상 결과로 안내(5.8).
- **예외 처리(PRD 5장)** — 19개 항목 중 15개(5.1~5.3, 5.6, 5.8~5.19)가 구현됨.
  - **단일 상태 계산**: `app/page.tsx`의 `getDisplay()`가 `inputError`/`isOffline`/`requestPhase`/`isSlow` 네 원시 상태를 우선순위(입력오류 > 오프라인 > 로딩·지연 > 타임아웃·서버오류 > 성공)로 조합(5.18).
  - **5.1** 빈 입력 시 포커스 이동·테두리 강조, **5.4/5.5** 지연(4초)·타임아웃(18초, `AbortController`), **5.6** 무제한 재시도(실제 502로 검증됨), **5.7** `generatePartialSafe`(`lib/ai.ts`)가 AI 응답을 필드 단위로 재검증해 살아남은 필드만 쓰고 나머지는 `null`→placeholder, **5.11** 로딩 중 탭 전환까지 차단, **5.12** 온라인/오프라인 감지, **5.13** 글자 수 카운터+제한(서버도 재검증).
  - **5.14 XSS**: `dangerouslySetInnerHTML` 0건, `<script>` 페이로드를 서버까지 실제로 넣어 확인. 모든 사용자 텍스트는 JSX 텍스트 노드로만 렌더링.
  - **5.15/5.16 클립보드**: `lib/use-copy.ts`(`useCopyToClipboard`)로 성공(체크 아이콘)/실패(토스트) 피드백을 `CopyButton`·`CodeBlock`이 공유. 작업 중 `AlgorithmResult`의 "예시 코드" 카드에 있던 불필요한 `overflow-hidden`이 이 토스트를 가리는 버그를 발견해 제거.
  - **5.17 모바일**: 입력 포커스 시 `scrollIntoView`(가상 키보드 회피), 아이콘 전용 버튼(복사·테마·언어 재시도)의 클릭 영역을 `after:-inset-*` 가상요소로 시각적 크기 변화 없이 ~44px까지 확대, 언어/풀이 서브탭 패딩 확대. 탭 2등분·콤보박스 스크롤은 이전 스프린트부터 이미 있었음.
  - **3.4 로딩 오버레이 범위**: `loading` 상태에서는 `LoadingState`만 렌더링되고 결과·버튼(`AlgorithmResult`/`ProblemResult`)은 `success`에서만 렌더링되는 구조라 애초에 요구사항을 만족 — 코드 감사로 확인, 수정 불필요.
- **검증 완료 범위**: `tsc --noEmit`, `pnpm build` 모두 통과. node fetch로 세 API 라우트의 입력 검증/에러 코드 전부 확인, XSS 페이로드 라운드트립 확인. `AI_GATEWAY_API_KEY`가 없어 (1) 두 기능의 AI 성공 응답 렌더링, (2) 5.4/5.5/5.7/5.19의 실제 AI 트래픽 재현, (3) 브라우저를 통한 5.1/5.12/5.15/5.17/5.18의 육안 확인·모바일 반응형 QA는 아직 하지 못했다(이번 세션은 브라우저 자동화 도구 없이 진행됨).

| 영역 | PRD 요구 | 현재 상태 |
|---|---|---|
| AI 성공 응답 육안 확인 | 실제 200 응답이 화면에 의도대로 채워지는지 | `AI_GATEWAY_API_KEY`가 없어 두 기능 모두 아직 못 봄 — 키가 생기는 대로 아무 때나 가능 |
| 브라우저 육안/모바일 QA | 5.1/5.4/5.5/5.7/5.12/5.15/5.17/5.18 등 다수 항목의 실제 화면 확인 | 코드·로직은 갖춰졌으나 이번 세션은 브라우저 도구 없이 진행되어 미확인 |
| Done Criteria 1~8 전체 재검증 | PRD 6장 완료 조건 재현 | 아직 종합적으로 실행 안 함 — **Sprint 5** |
| 프로덕션 배포 | Vercel 배포 | 아직 로컬 개발 서버까지만 — **Sprint 5** |

## 결론

Sprint 0~4로 PRD 4장(핵심 파이프라인)과 5장(예외 처리) 19개 항목의 **코드가 전부 갖춰졌다**. 개발 관점에서 남은 작업은 실질적으로 검증뿐이다: (1) `AI_GATEWAY_API_KEY`를 확보해 두 기능의 실제 AI 응답을 눈으로 확인, (2) 브라우저(가급적 모바일 포함)로 5장 예외 상황들을 하나씩 재현해 문구/동작이 PRD와 정확히 일치하는지 확인, (3) Done Criteria 1~8 통합 QA 후 배포(Sprint 5). 다음 착수 지점은 `03-sprint-plan.md`의 Sprint 5 — 단, AI 키 확보와 브라우저 QA가 선행되어야 실질적인 진행이 가능하다.
