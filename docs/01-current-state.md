# 현재 상태 (Baseline Audit)

작성일: 2026-08-28 · 커밋: `65a7612` 기준

PRD가 요구하는 최종 형태와, 지금 리포지토리에 실제로 존재하는 것 사이의 간극을 정리한다. 스프린트 계획(`03-sprint-plan.md`)은 이 간극을 메우는 순서다.

## 존재하는 것

- **UI 셸**: `app/page.tsx`에 탭 전환(알고리즘/문제), 상단 헤더, 다크모드 토글이 구현되어 있음.
- **컴포넌트**: `AlgorithmCombobox`, `AlgorithmResult`, `ProblemResult`, `CodeBlock`, `CopyButton`, `DifficultyBadge`, `IdleState`/`LoadingState`/`ErrorState` 가 모두 존재.
- **정적 데이터**: `lib/algorithms.ts`에 알고리즘 10여 개가 하드코딩되어 있음(이진 탐색, 퀵 정렬 등). 각 알고리즘은 설명/난이도/난이도 근거/사용처/관련 알고리즘/**단일 언어 코드 1개**를 가짐.
- **문제 검색**: `MOCK_PROBLEM_RESULT` 라는 고정 목업 하나만 존재. 입력값과 무관하게 항상 같은 결과가 나옴.
- **로딩 흉내**: `runWithLoading()`이 `setTimeout(650ms)`으로 로딩을 흉내내고 무조건 성공 처리함.

## PRD 대비 빠진 것 (핵심 간극)

| 알고리즘 목록 범위 | "사실상 모든 알고리즘"을 포괄하는 사전 정의 목록 (3.1) | 10여 개뿐 |

## 결론

지금 상태는 "화면 골격과 디자인 시스템은 갖춰진 정적 프로토타입"이다. 실질적인 제품 로직(AI 연동, 데이터 범위, 예외 처리)은 이번 계획으로 전부 새로 구현해야 한다. 기존 컴포넌트는 가능한 한 재사용하되, `lib/algorithms.ts`의 데이터 구조와 `page.tsx`의 상태 관리 로직은 스프린트 0~1에서 대부분 교체된다.
