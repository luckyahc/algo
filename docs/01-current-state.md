# 현재 상태 (Baseline Audit)

작성일: 2026-08-28 (Sprint 0~5 진행 후 — 개발 완료, 배포는 미완료)

PRD가 요구하는 최종 형태와, 지금 리포지토리에 실제로 존재하는 것 사이의 간극을 정리한다. 스프린트 계획(`03-sprint-plan.md`)은 이 간극을 메우는 순서다.

## 구현되어 있는 것

- **알고리즘 검색(기능 A)** — 실제 AI 연동으로 동작한다.
  - `lib/algorithm-catalog.ts`: 82개 항목의 유효 알고리즘 목록(PRD 3.1).
  - `app/api/algorithm/route.ts` + `app/api/algorithm/code/route.ts`: 설명·난이도·근거·사용처·C/C++/Java/Python 코드·관련 알고리즘 생성, 언어 하나만 개별 재생성(5.19).
  - `components/language-tabs.tsx`: 언어 탭, 세션 내 선택 유지(3.2), 실패한 언어는 탭 안 재시도 버튼.
  - 관련 알고리즘: 서버·클라이언트 이중 자기참조/무효 id 필터링(5.9, 5.10).
- **문제 검색(기능 B)** — 실제 AI 연동으로 동작한다.
  - `app/api/problem/route.ts`: 난이도·근거·매칭 여부(`matched`)·풀이별 목록 생성, 무효 `algorithmId` 필터링.
  - `components/problem-result.tsx`: 풀이 여러 개면 탭 + 시간복잡도, 매칭 없음은 정상 결과로 안내(5.8).
- **예외 처리(PRD 5장)** — 19개 항목 전부 코드로 구현됨(5.1~5.19).
  - **단일 상태 계산**: `app/page.tsx`의 `getDisplay()`가 `inputError`/`isOffline`/`requestPhase`/`isSlow` 네 원시 상태를 우선순위(입력오류 > 오프라인 > 로딩·지연 > 타임아웃·서버오류 > 성공)로 조합(5.18).
  - 빈 입력 포커스/강조(5.1), 무의미 입력 차단(5.2), 카탈로그 불일치 처리(5.3), 지연(5.4)·타임아웃(5.5), 무제한 재시도(5.6), 필드 단위 부분 파싱 복구(5.7, `lib/ai.ts`의 `generatePartialSafe`), 매칭 없음 정상 처리(5.8), 무효 관련 알고리즘/자기참조 필터링(5.9, 5.10), 로딩 중 탭 전환까지 차단(5.11), 온라인/오프라인 감지(5.12), 글자 수 제한(5.13), XSS 안전(5.14), 클립보드 성공/실패 피드백(5.15, 5.16), 모바일 터치 타겟/키보드 회피(5.17), 상태 우선순위(5.18), 언어별 개별 재시도(5.19).
- **Sprint 5(QA)에서 발견해 고친 것**: `app/page.tsx`에 React 에러 바운더리가 없어, 결과 렌더링 중 예기치 못한 오류가 나면 헤더·탭·입력창까지 전부 죽어 Done Criteria #6("항상 상태 표시줄과 입력 UI는 살아있어야 한다")을 위반할 수 있었다. `components/result-error-boundary.tsx`(`ResultErrorBoundary`)를 새로 만들어 결과 렌더링 구간만 감싸도록 수정 — 이제 그 구간 오류는 결과 영역만 재시도 화면으로 바뀌고 나머지 UI는 그대로 살아있다.
- **검증 완료 범위**: `tsc --noEmit`, `pnpm build` 모두 통과. 세 API 라우트(`/api/algorithm`, `/api/problem`, `/api/algorithm/code`)의 성공/실패 케이스 10가지를 이번 세션에 다시 실행해 회귀 없음을 확인. `login/payment/upload/저장하기` 등 범위 밖 UI가 코드에 전혀 없음을 grep으로 확인(Done Criteria #7). XSS 페이로드 서버 라운드트립 확인(5.14).
- **아직 못 한 것**: (1) `AI_GATEWAY_API_KEY`가 없어 AI 성공 응답이 실제로 화면을 채우는지 확인 못 함, (2) 이번 세션은 브라우저 자동화 도구 없이 진행되어 지연/타임아웃/오프라인/클립보드/모바일 반응형 등 다수 항목의 브라우저 육안 확인을 못 함, (3) Vercel 프로덕션 배포는 사용자 본인의 로그인(OAuth)이 필요해 진행하지 못함 — CLI는 설치해 두었다(`vercel --version` 확인됨).

## PRD 대비 남은 간극

| 영역 | PRD 요구 | 현재 상태 |
|---|---|---|
| AI 성공 응답 육안 확인 | 실제 200 응답이 화면에 의도대로 채워지는지 | `AI_GATEWAY_API_KEY`가 없어 두 기능 모두 아직 못 봄 |
| 브라우저 육안/모바일 QA | 5.1/5.4/5.5/5.7/5.12/5.15/5.17/5.18 등 다수 항목의 실제 화면 확인 | 코드·로직은 갖춰졌으나 브라우저 도구 없이 진행되어 미확인 |
| Done Criteria 1~8 전체 재검증 | PRD 6장 완료 조건 재현 | #4/#7만 실제 실행됨, #3/#5/#6/#8은 코드 검증만, #1/#2는 AI 키로 전면 블록 (`03-sprint-plan.md`의 "QA 결과" 표 참고) |
| 프로덕션 배포 | Vercel 배포 | **차단됨** — `vercel login`은 사용자 본인이 브라우저에서 진행해야 하는 OAuth 흐름이라 에이전트가 대신할 수 없음. CLI만 설치 완료 |

## 결론

Sprint 0~5로 PRD 4장(핵심 파이프라인)과 5장(예외 처리) 19개 항목 전부의 **코드가 갖춰졌고**, Sprint 5 QA 과정에서 에러 바운더리 부재라는 실제 버그를 하나 발견해 고쳤다. 이제 이 프로젝트의 병목은 코드가 아니라 두 가지 외부 자원이다: (1) `AI_GATEWAY_API_KEY` — 있어야 AI 성공 응답과 5.4/5.5/5.7/5.19 같은 항목을 실제로 볼 수 있다, (2) 사용자 본인의 Vercel 로그인 — 있어야 배포와 프로덕션 URL 기준 최종 QA가 가능하다. 둘 다 에이전트가 대신 확보할 수 없는 자원이라, 다음 단계는 사용자가 이 둘을 준비하는 것이다.
