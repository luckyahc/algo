# 예외 처리 체크리스트 (PRD 5장)

PRD `5장 예외 처리`의 19개 항목을 구현 상태와 함께 추적한다. 담당 스프린트는 `03-sprint-plan.md` 기준이며, 실제 작업 시 이 표를 갱신한다.

상태 값: `미착수` / `진행중` / `완료(미검증)` / `완료(검증됨)`

| PRD | 항목 | 담당 스프린트 | 상태 |
|---|---|---|---|
| 5.1 | 빈 입력으로 검색 시도 | Sprint 3 | 완료(미검증) — 상태 표시줄 문구 + 입력창 포커스/테두리 강조(`highlightError`) 구현. 브라우저 육안 확인 아직 안 함 |
| 5.2 | 공백/특수문자만으로 이루어진 무의미한 입력 | Sprint 2 | 완료(검증됨) — `hasMeaningfulContent`로 클라이언트+서버 모두 확인, node fetch로 "....."/"ㅋㅋㅋ" 케이스 400 확인 |
| 5.3 | 자동완성 목록에 없는 알고리즘 이름 입력 | Sprint 1 | 완료(검증됨) — 서버(400/404)·클라이언트(`input-error` 상태) 양쪽 확인 |
| 5.4 | AI 응답 지연 (3~5초) | Sprint 3 | 완료(미검증) — 4초 후 `isSlow` 전환 + 문구 갱신 구현. 실제 AI 응답 지연 상황으로는 재현 못 함 |

| 5.6 | AI 처리 중 오류 (네트워크/서버/API) | Sprint 3 | 완료(검증됨) — 잘못된 키로 실제 502를 받아 `ErrorState` + 무제한 재시도가 정상 동작함을 확인(당시엔 Vercel AI Gateway 키; 2026-08-28 Gemini로 전환된 지금도 코드 경로는 동일) |
| 5.7 | 형식에 맞지 않는 응답 (파싱 실패, 부분 표시) | Sprint 3 | 완료(미검증) — `generatePartialSafe`로 필드 단위 salvage + null 필드 placeholder 렌더링 구현. 2026-08-28 Gemini 키로 전환 후 관찰한 실제 응답은 전부 스키마를 완전히 만족해 `'ok'` 경로만 탔다 — `'partial'` salvage 경로는 아직 실제 AI 응답으로 발동한 적 없음(Sprint 6 과제) |

| 5.9 | 관련/추천 알고리즘 버튼이 무효 데이터를 가리킴 | Sprint 1 | 완료(미검증) — 로직은 구현, AI가 실제로 무효 id를 생성하는 사례로는 아직 못 봄 |
| 5.10 | 순환 참조/자기 참조로 인한 무한 루프 우려 | Sprint 1 | 완료(미검증) — 서버·클라이언트 이중 필터링 구현, 실제 AI 응답으로는 미검증 |
| 5.11 | 중복 클릭/연타로 인한 중복 요청 | Sprint 3 | 완료(검증됨) — 로딩 중 검색창/버튼뿐 아니라 **탭 전환도** 막도록 보강(요청 완료 시 엉뚱한 탭에 결과가 뜨는 것을 방지). 코드 감사로 확인, `tsc`/`build` 통과 |

| 5.13 | 매우 긴 입력값 (글자 수 초과) | Sprint 3 | 완료(검증됨) — 클라이언트 카운터+버튼 비활성화, 서버(`/api/problem`)에서 1000자 초과 시 400(`TOO_LONG`)도 node fetch로 확인 |
| 5.14 | 악의적 입력/스크립트 삽입 시도 (XSS) | Sprint 4 | 완료(검증됨) — `dangerouslySetInnerHTML` 전체 검색 0건, `<script>` 페이로드를 실제로 `/api/problem`에 넣어 서버 라운드트립까지 확인. 화면 렌더링은 모든 사용자 텍스트가 JSX 텍스트 노드라 구조적으로 안전 |

| 5.17 | 모바일 환경 레이아웃/입력 이슈 | Sprint 4 | 완료(미검증) — 입력 포커스 시 `scrollIntoView`, 아이콘 버튼들 터치 영역 확대(`after:-inset-*`), 탭류 버튼 패딩 확대 추가. 실기기/브라우저 반응형 모드 육안 확인은 아직 못 함 |

## 검증 방법 메모

- 5.1: 브라우저에서 빈 값으로 검색해 포커스 이동 + 테두리 강조 + 문구를 육안으로 확인할 것.
- 5.4/5.5/5.7: `GOOGLE_GENERATIVE_AI_API_KEY` 확보로 실제 AI 트래픽 재현이 가능해졌다(2026-08-28). 5.19는 이미 실제 트래픽으로 검증됨. 5.4/5.5/5.7은 여러 번 호출하며 관찰하거나, `lib/request-timing.ts`의 상수를 임시로 짧게 낮춰 타이머 분기 자체만 로컬에서 확인하는 방법도 있다.
- 5.12: 브라우저 devtools의 오프라인 모드로 재현.
- 5.14: `<script>alert(1)</script>` 등을 실제로 입력해 렌더링 결과가 텍스트로만 보이는지 확인.
- 5.18: 오프라인 상태에서 빈 입력으로 검색을 시도해, 입력오류 문구가 오프라인 문구보다 먼저 나오는지 확인 (우선순위 1 > 2).
- 5.15: 클립보드 권한을 거부하거나(브라우저 설정) `navigator.clipboard`가 없는 환경(예: 비보안 컨텍스트)에서 복사를 눌러 실패 토스트가 뜨는지 확인.
- 5.17: 브라우저 개발자도구의 반응형 모드(iPhone SE 등 좁은 폭)로 두 탭/자동완성 드롭다운/입력 포커스 스크롤/버튼 터치 크기를 확인. 실기기 확인이 가장 확실하다.
